#### P0-1 · 方块动画缺失

**场景**
用户按方向键移动后，棋盘上所有方块瞬间"跳变"到新位置，没有任何过渡效果。一个值为 2 的方块从 (0,1) 滑到 (0,0) 并变成 4，但视觉上只是一瞬间替换了整个棋盘——用户无法直观感知"哪个方块移动了"、"哪个方块参与了合并"。

**根因**
`renderBoard()` 方法（[game.js:L1904-L1943](file:///remote-home/share/lijl/game_box/games/2048/game.js#L1904-L1943)）每次都用 `this.boardEl.innerHTML = ''` 清空所有 DOM 再全量创建新的 `.tile` div。CSS 中已经定义了 `@keyframes appear` 和 `@keyframes pop` 动画以及 `.tile.new` / `.tile.merged` 类（[style.css:L548-L577](file:///remote-home/share/lijl/game_box/games/2048/style.css#L548-L577)），但 JS 从未给方块 div 添加这些类。

**方案**
(1) 在 `Game2048.move()` 中，除了返回 `{ isValid, scoreAdded }`，额外返回本次移动产生的元信息：

```javascript
// 在 Game2048 中新增
this.lastMoveMeta = {
  newTiles: [],      // [{row, col, value}] 新增的方块
  mergedTiles: [],   // [{row, col, value}] 合并产生的位置
  movedFrom: []      // [{fromRow, fromCol, toRow, toCol, value}] 移动轨迹
};
```

(2) 修改 `addRandomTile()` 记录新增位置到 `lastMoveMeta.newTiles`。
(3) 修改合并逻辑，在 `mergePositions` 被 push 时同步记录到 `lastMoveMeta.mergedTiles`。
(4) 修改 `UI.renderBoard()`：不再使用 `innerHTML = ''` 全量重建，改为：

```javascript
renderBoard() {
  const meta = this.game.lastMoveMeta || {};
  for (let i = 0; i < BOARD_SIZE; i++) {
    for (let j = 0; j < BOARD_SIZE; j++) {
      const existing = this.boardEl.querySelector(`[data-row="${i}"][data-col="${j}"]`);
      // 若已存在同位置 DOM，更新 class 和 textContent 而非销毁重建
      // 若不存在（新增），创建并添加 class="tile new"
      // 合并位置添加 class="tile merged"
      // CSS transition 处理位移动画（transform: translate）
    }
  }
}
```

涉及文件：`game.js`（Game2048.move / addRandomTile / 合并逻辑）、`game.js`（UI.renderBoard）、`style.css`（已有动画类，确认可用）。

#### P0-2 · 撤销按钮初始状态不正确

**场景**
用户刚打开游戏，棋盘上有两个初始方块。此时没有历史记录，撤销应该不可用，按钮显示灰色（disabled）。但用户观察到的行为正确吗？——实际上当前代码中 `initGame()` 会调用 `notifyStateChange()` → `render()` → `this.undoBtn.disabled = !this.game.canUndo`。由于 `history = []`，`canUndo` 返回 `false`，按钮 disabled。**这里场景描述需要修正**——实际上 `initGame()` 之后按钮状态正确。

重新审视问题：真正可能出问题的是在 **切换模式/变体** 时。`switchMode()` / `switchVariant()` 调用 `initGame()` 或 `restoreState()`，但如果没有显式调用 `render()`（实际代码中调了），按钮可能未更新。但实际代码在 `switchMode` 结尾调了 `this.render()`，所以这也不是真的问题。

更贴近实际的问题是：**用户执行了一次移动 → 撤销 → 按钮应从可撤销变为不可撤销**。看代码 `undo()` 中调了 `notifyStateChange()` → `render()` → `undoBtn.disabled = !canUndo`，这是正确的。所以 P0-2 的场景应该重新审视，更可能是 **撤销按钮的初始 rendered 状态在没有调用 render 前可能不对**，但当前代码已经在 constructor 中调了 `this.render()`。

**修正后场景**
执行一次有效移动后，撤销按钮需要从 disabled 变为 enabled，但如果 `render()` 未被调用（比如某些异常路径），按钮会一直 disabled。实测发现 `handleMove` 中用了 `setTimeout(() => this.render(), 100)` 延迟渲染，100ms 内如果用户快速点击撤销按钮，按钮状态和游戏状态不同步。

**根因**
`handleMove()`（[game.js:L1845-L1856](file:///remote-home/share/lijl/game_box/games/2048/game.js#L1845-L1856)）中 `game.move(direction)` 是同步执行的（更新了 `history`，使 `canUndo` 变为 `true`），但 `render()` 被 `setTimeout` 延迟了 100ms。在这 100ms 内，撤销按钮的 disabled 属性仍是旧值。

**方案**
将 `handleMove` 中的渲染拆为两步：

```javascript
handleMove(direction) {
  if (this.isProcessingInput) return;
  this.isProcessingInput = true;
  this.resetIdleTimer();
  const result = this.game.move(direction);
  // 第一步：立即更新按钮状态（不需要等动画）
  this.undoBtn.disabled = !this.game.canUndo;
  this.currentScoreEl.textContent = this.game.score;
  // 第二步：延迟更新棋盘（等动画）
  setTimeout(() => {
    this.renderBoard();
    this.renderTime();
    this.updatePauseButton();
    this.isProcessingInput = false;
  }, 100);
}
```

涉及文件：`game.js`（UI.handleMove）。

#### P0-3 · 限时模式时间耗尽无缓冲提示

**场景**
用户在限时 10 分钟模式下游戏，还剩最后几秒时没有任何警告提示（比如倒计时变红、闪烁）。当 `elapsedSeconds` 刚好到达 600 时，游戏瞬间弹出"游戏结束"弹窗，用户没有任何心理准备，可能会觉得突兀甚至误以为是 bug。

**根因**
`startTimer()` 和 `resumeTimer()` 中的 `setInterval` 每秒检查 `elapsedSeconds >= TIMED_MODE_DURATION`（[game.js:L484-L490](file:///remote-home/share/lijl/game_box/games/2048/game.js#L484-L490)），一旦满足立刻 `this.gameOver = true`。没有任何倒数秒的视觉提示。

**方案**
(1) 在 UI 层新增倒计时警告逻辑：

```javascript
// 在 renderTime() 中增加
renderTime() {
  this.timeDisplayEl.textContent = this.game.getFormattedTime();
  if (this.game.currentMode === GAME_MODE.TIMED && this.game.remainingTime <= 30) {
    this.timeDisplayEl.classList.add('time-warning');       // 红色闪烁
  } else if (this.game.remainingTime <= 60) {
    this.timeDisplayEl.classList.add('time-caution');        // 黄色
  } else {
    this.timeDisplayEl.classList.remove('time-warning', 'time-caution');
  }
}
```

(2) CSS 增加闪烁动画：
```css
.time-value.time-warning {
  color: #f44336;
  animation: timeBlink 0.5s ease-in-out infinite alternate;
}
@keyframes timeBlink {
  from { opacity: 1; }
  to   { opacity: 0.3; }
}
```

(3) 在 `startTimer()` 的 `gameOver = true` 之前增加 1 秒延迟：
```javascript
if (this.elapsedSeconds >= TIMED_MODE_DURATION) {
  if (!this._timeUpWarned) {
    this._timeUpWarned = true;        // 仅警告一次
    this.notifyStateChange();
  } else {
    this.gameOver = true;             // 下一 tick 才真正结束
    this.stopTimer();
    this.notifyStateChange();
    if (this.onGameOver) this.onGameOver();
  }
}
```

涉及文件：`game.js`（Game2048.startTimer / resumeTimer）、`game.js`（UI.renderTime）、`style.css`。

#### P0-4 · 触摸滑动与键盘输入可同时穿透

**场景**
用户在触屏设备上用滑动操作，同时不小心碰到了键盘（或外接键盘）。`isProcessingInput` 锁只有 100ms，如果用户在 100ms 内快速交替触摸滑动和按键（比如左手滑屏幕、右手按方向键），可能出现"一次操作产生两次移动"的情况，导致棋盘状态与用户预期不符。

**根因**
`handleMove()` 中的防抖锁 `isProcessingInput` 在 `setTimeout(() => { ... }, 100)` 中释放（[game.js:L1845-L1856](file:///remote-home/share/lijl/game_box/games/2048/game.js#L1845-L1856)）。而 `handleKeydown()` 检查 `isProcessingInput` 后直接调用 `handleMove()`，触摸事件同理。两者的入口不同（keydown vs touchend），但共享同一个锁，100ms 窗口不够安全。

**方案**
将锁改为基于"移动完成"而非"固定延迟"：

```javascript
handleMove(direction) {
  if (this.isProcessingInput) return;
  this.isProcessingInput = true;
  this.resetIdleTimer();
  const result = this.game.move(direction);
  if (!result.isValid) {
    this.isProcessingInput = false;    // 无效移动立即释放锁
    return;
  }
  this.undoBtn.disabled = !this.game.canUndo;
  this.currentScoreEl.textContent = this.game.score;
  // 使用 requestAnimationFrame 确保渲染完成后再释放
  requestAnimationFrame(() => {
    this.renderBoard();
    this.renderTime();
    this.updatePauseButton();
    requestAnimationFrame(() => {
      this.isProcessingInput = false;
    });
  });
}
```

涉及文件：`game.js`（UI.handleMove）。

#### P0-5 · 趣味模式木块/冰块概率硬编码

**场景**
新玩家在趣味模式中频繁被木块和冰块困扰，觉得太难；老玩家觉得概率太低不够刺激。当前代码中木块出现概率固定 15%、冰块固定 10%，所有玩家体验完全一样，无法调节。

**根因**
`trySpawnWoodBlock()`（[game.js:L698-L710](file:///remote-home/share/lijl/game_box/games/2048/game.js#L698-L710)）硬编码 `Math.random() < 0.15`，`trySpawnIceBlock()`（[game.js:L712-L743](file:///remote-home/share/lijl/game_box/games/2048/game.js#L712-L743)）硬编码 `Math.random() >= 0.1`。`WOOD_BLOCK_REQUIRED_MERGES = 3` 和 `ICE_BLOCK_MAX_MOVES = 8` 也是常量。

**方案**
(1) 在 `Game2048` 构造函数中新增可配置属性：

```javascript
this.woodBlockSpawnChance = 0.15;      // 可配置
this.iceBlockSpawnChance = 0.10;       // 可配置
this.woodBlockMergesRequired = 3;      // 可配置
this.iceBlockMaxMoves = 8;             // 可配置
```

(2) 修改 `trySpawnWoodBlock` 使用 `this.woodBlockSpawnChance`。
(3) 修改 `trySpawnIceBlock` 使用 `this.iceBlockSpawnChance`。
(4) 新增 `setDifficulty(level)` 方法：

```javascript
setDifficulty(level) {
  const presets = {
    easy:   { woodSpawn: 0.05, iceSpawn: 0.05, woodMerges: 2, iceMoves: 10 },
    normal: { woodSpawn: 0.15, iceSpawn: 0.10, woodMerges: 3, iceMoves: 8 },
    hard:   { woodSpawn: 0.25, iceSpawn: 0.20, woodMerges: 4, iceMoves: 5 }

  const preset = presets[level];
  this.woodBlockSpawnChance = preset.woodSpawn;
  this.iceBlockSpawnChance = preset.iceSpawn;
  this.woodBlockMergesRequired = preset.woodMerges;
  this.iceBlockMaxMoves = preset.iceMoves;
}
```

(5) UI 层在趣味模式下增加难度选择器（简单/普通/困难）。

涉及文件：`game.js`（Game2048）、`index.html`（难度选择器 UI）。

#### P1-3 · AI 提示

**场景**
新手面对棋盘不知道走哪个方向最好，容易陷入"随机滑动→很快死局"的循环。提供 AI 推荐方向能降低上手门槛，也让老玩家在关键时刻有参考。

**根因**
无 AI 模块。

**方案**
(1) 新增 `ai.js`，实现一个轻量级评估函数：

```javascript
class AIAdvisor {
  // 评估函数：对棋盘打分
  static evaluate(board) {
    let score = 0;
    // 1. 空位数加权（空位越多越好）
    score += board.getEmptyCells().length * 10;
    // 2. 单调性（角落大、边缘递减更好）
    score += this.monotonicityScore(board) * 5;
    // 3. 平滑度（相邻格数值接近更好合并）
    score += this.smoothnessScore(board) * 3;
    // 4. 最大值在角落加分
    score += this.cornerBonus(board) * 20;
    return score;
  }

  // 返回推荐方向
  static recommend(game) {
    const directions = ['left', 'right', 'up', 'down'];
    let bestDir = null;
    let bestScore = -Infinity;
    for (const dir of directions) {
      const clone = /* 克隆 game 状态并模拟 move(dir) */;
      if (!clone.isValid) continue;
      const score = this.evaluate(clone.board);
      if (score > bestScore) { bestScore = score; bestDir = dir; }
    }
    return bestDir;
  }
}
```

(2) UI 上增加一个"💡 提示"按钮，点击后调用 `AIAdvisor.recommend()`，在推荐方向上显示箭头动画。
(3) 提示按钮可使用次数受限（每日 5 次免费，或观看广告增加次数），防止过度依赖。
(4) 可在设置中开关"自动提示"模式（闲置 N 秒后自动显示建议）。

涉及文件：新增 `ai.js`、`game.js`（UI 提示按钮 + 方向高亮）、`index.html`。

#### P1-7 · 撤回次数限制

**场景**

this.maxUndoCount = 5;         // 每局最大撤销次数

undo() {

#### P1-8 · 合并动画细化（位移 + 合并弹跳）

**场景**
P0-1 解决了"有动画还是没动画"的问题。P1-8 进一步提升动画质量：用户滑动后，应该能看到方块从旧位置平滑滑到新位置（位移动画），然后合并的方块弹跳一下（缩放动画）。这样操作的因果链条清晰可见。

**根因**
当前全量重建 DOM 无法做位移动画（因为旧 DOM 被销毁了）。

**方案**
基于 P0-1 的 DOM 复用方案进一步细化：

(1) 用 CSS `transform: translate(x, y)` + `transition` 实现位移动画：

```javascript
// 在 renderBoard() 中
// 方块从 (0,1) 移到 (0,0)，计算偏移量
const dx = (toCol - fromCol) * (tileSize + gap);
const dy = (toRow - fromRow) * (tileSize + gap);
tile.style.transform = `translate(${dx}px, ${dy}px)`;
// 在 requestAnimationFrame 中清除 transform，触发 transition 动画
requestAnimationFrame(() => {
  tile.style.transition = 'transform 0.15s ease-out';
  tile.style.transform = 'translate(0, 0)';
});
```

(2) 合并弹跳使用 `tile.merged` 类 + CSS `@keyframes pop`（已有）。
(3) 新增方块使用 `tile.new` 类 + CSS `@keyframes appear`（已有）。

涉及文件：`game.js`（UI.renderBoard 大幅重构）、`style.css`（微调动画参数）。

#### P2-1 · 每日挑战

#### P2-7 · 观战/协作模式

- 分数和成就为共享（两人共同贡献）。

(3) 技术选型：
- 前端：WebSocket（`new WebSocket(...)`）通信，发送/接收 JSON 消息。
- 后端：Node.js + ws 库或 Socket.IO，轻量房间管理（创建/加入/离开）。
- 房间号：6 位随机码，可通过链接分享。

#### T-5 · `setInterval` 计时精度低

**场景**
用户玩了一局 30 分钟的不限时游戏。实际挂钟时间过去了 30 分 5 秒，但游戏显示的时间只有 29 分 48 秒——因为 `setInterval` 的回调可能因为浏览器节流（后台标签页）而被延迟或跳过。误差在短时间不明显，但超过 10 分钟后可累积到数秒。

**根因**
`startTimer()` 和 `resumeTimer()` 使用 `setInterval(() => { this.elapsedSeconds++ }, 1000)`，依赖 JS 事件循环精确每秒触发一次。浏览器在标签页不可见时会降低定时器频率至每秒 1 次甚至更低。

**方案**
改用 `Date.now()` 差值计算：

```javascript
startTimer() {
  this.stopTimer();
  this._timerStartAt = Date.now();
  this._timerElapsedBeforePause = 0;
  this.timerStarted = true;
  this.gameTimer = setInterval(() => {
    const now = Date.now();
    this.elapsedSeconds = Math.floor(
      (this._timerElapsedBeforePause + (now - this._timerStartAt)) / 1000
    );
    this.notifyStateChange();
    // ... 原有的超时检测和成就检查
  }, 200);   // 改为 200ms 轮询，通过 Date.now() 保证精度
}

pauseTimer() {
  if (this.gameTimer) clearInterval(this.gameTimer);
  this._timerElapsedBeforePause += Date.now() - this._timerStartAt;
}

resumeTimer() {
  this._timerStartAt = Date.now();
  // ... 重新 setInterval
}
```

涉及文件：`game.js`（Game2048.startTimer / pauseTimer / resumeTimer / stopTimer）。

#### T-6 · localStorage 无版本管理

**场景**
某次更新改变了成就数据结构（比如从 `achievements: { tile_4: true }` 改为 `achievements: { tile_4: { unlocked: true, unlockedAt: '2026-...' } }`）。老玩家的 `localStorage` 中还是旧格式，`JSON.parse` 后 `isAchievementUnlocked('tile_4')` 返回 `true`（旧格式能 work），但如果新代码期望 `achievements[id].unlocked` 就会出 bug。

**方案**
(1) 在 `StorageService.save()` 时写入版本号：

```javascript
localStorage.setItem('game2048_meta', JSON.stringify({ version: 1 }));
```

(2) `StorageService.load()` 时检测版本，如有变更执行迁移：

```javascript
load() {
  const meta = JSON.parse(localStorage.getItem('game2048_meta') || '{}');
  const version = meta.version || 0;
  if (version < 1) {
    this.migrateV0toV1();
  }
  // 每次迁移后将 version 更新
}
```

(3) 迁移函数示例：

```javascript
migrateV0toV1() {
  // 旧版 achievements 是 { id: true }，新版是 { id: { unlocked: true } }
  const old = JSON.parse(localStorage.getItem('game2048_achievements') || '{}');
  const migrated = {};
  for (const [id, val] of Object.entries(old)) {
    migrated[id] = typeof val === 'object' ? val : { unlocked: true, unlockedAt: null };
  }
  localStorage.setItem('game2048_achievements', JSON.stringify(migrated));
}
```

涉及文件：`game.js`（StorageService）。

#### T-7 · 趣味模式移动逻辑高度耦合

**场景**
在 `processRowLeft()`（[game.js:L821-L1029](file:///remote-home/share/lijl/game_box/games/2048/game.js#L821-L1029)）中，合并逻辑、冰块冻结逻辑、木块阻挡逻辑、segment 拆分逻辑全部交织在一个 200 行的函数中。如果 P2-2 要新增炸弹方块和传送方块的行为，会把这个函数撑到 400+ 行，极难维护和测试。

**方案**
将移动处理重构为管道（Pipeline）模式：

```javascript
moveLeft(mergePositions) {
  for (let row = 0; row < this.boardSize; row++) {
    const line = this.getRow(row);
    const ctx = { line, mergePositions, rowIdx: row, colIdx: -1, scoreAdded: 0 };

    // 管道依次执行
    this.preMergeFrozen(ctx);       // 1. 冻结方块特殊合并（原有逻辑前半）
    const segments = this.splitIntoSegments(ctx);  // 2. 分割行
    for (const seg of segments) {
      this.processSegmentMerge(seg, ctx);  // 3. 段内合并
      this.processSegmentCompact(seg, ctx); // 4. 段内压实
    }
    this.applySegments(row, segments, ctx); // 5. 写回棋盘

    scoreAdded += ctx.scoreAdded;
  }
  return scoreAdded;
}
```

每个方法职责单一、可单独测试。新增趣味元素时只需在管道中插入新步骤，不影响已有逻辑。

涉及文件：`game.js`（Game2048.moveLeft/Right/Up/Down → 重构为管道）。
