# 2048 游戏问题记录

## 问题 1：锁链合并检测与倒计时逻辑

### 问题现象
1. 锁链方块（8）与相邻普通数字（2）绑定后，向左滑动时，锁链方块与左边的另一个8合并，合并后锁链直接被解除
2. 目标数字参与合并时，倒计时没有额外减少1
3. 锁链数字参与合并时，倒计时也没有额外减少1

### 问题原因
1. **合并位置检测错误**：原代码检查 `mr === oldChainPos[0] && mc === oldChainPos[1]` 来判断锁链是否参与合并，但合并发生在目标位置而非原来锁链的位置，匹配失败导致锁链被错误解除

2. **位置依赖错误**：在 `move` 函数中，调用顺序是先执行 `updateChainPairAfterMerge`（更新位置），然后才执行 `updateChainTimer`，所以 `updateChainTimer` 中位置已是更新后的新位置，找不到合并记录

3. **强制移动后阻挡物检查失败**：`constrainChainMovement` 会将 chain 和 target 整体移动到行的开头/结尾，但 `didCellMerge` 检查 originalBoard 上原始位置到合并位置之间是否有阻挡物，对被强制移动的 chain 会误判

### 解决方案
1. **重写 `updateChainPairAfterMerge` 函数**：
   - 通过比较原始棋盘和当前棋盘来判断锁链是否移动或合并
   - 通过合并位置的值和位置关系来正确识别锁链合并的位置
   - 确保合并后的单元格重新标记为锁链类型

2. **重写 `updateChainTimer` 函数**：
   - 直接从 `originalBoard` 获取原始位置
   - 分别独立检测锁链数字和目标数字的合并情况
   - 独立减少，可以叠加（两个都合并则总共减 3）

3. **新增 `didCellMerge` 辅助函数**：
   - 检查合并位置是否与原始位置完全相同
   - 或检查同一行/列中值为 2 倍的合并位置
   - 添加 `skipBlockerCheck` 参数：对于 chain/target（可能被强制移动），跳过阻挡物检查，只要合并位置上的值是原值的 2 倍就判定为参与了合并

## 问题 2：锁链绑定整体移动

### 问题现象
1. 锁链8和目标4绑定后，向下滑动时8被挡住但4继续向下滑动，导致两个绑定的数字分开
2. 锁链方块（16）与目标数字（2）绑定后，向右滑动时16被8挡住，锁链直接解除，只剩数字2还有锁链符号

### 问题原因
1. **移动逻辑逐行/列独立处理**：没有考虑锁链绑定的整体移动约束，`maintainChainAdjacency` 只是在移动完成后"修复"位置

2. **整体移动机制的Bug**：
   - `prepareChainForMovement` 将 target 临时转为 `Cell.chain()` 类型
   - `updateChainPairAfterMerge` 检测 target 是否移动时，因为临时转换使其 `isChain()` 为 true，被误判为"已移动"，触发 `releaseChain()`
   - `releaseChain` 只转换第一个 chain 方块回数字，遗漏了临时转换的 target
   - `finalizeChainMovement` 条件依赖 `this.chainPair` 不为 null，但 `releaseChain` 已将其置 null → 临时 target 永远无法还原

### 解决方案
1. **添加 `prepareChainForMovement` 函数**：在移动开始前检查锁链和目标是否在同一行/列，条件满足则标记为准备好整体移动

2. **添加 `constrainChainMovement` 函数**：在处理每行/列移动前，将锁链和目标作为整体移动到最前端

3. **添加 `finalizeChainMovement` 函数**：移动完成后清理状态标记，移到 `updateChainPairAfterMerge` 之前调用；条件中移除 `this.chainPair` 检查，确保即使 chain 已被释放，临时 target 也能被还原

4. **修复 `releaseChain`**：遍历整个棋盘，将所有 chain 方块转为数字，防止遗漏临时转换的 target

## 问题 3：锁链与传送阵交互问题

### 问题现象
锁链绑定的两个数字经过传送阵时，只有一个数字被传送，另一个留在原地，导致绑定关系被破坏。

### 问题原因
原 `processTeleportPortal` 函数只处理单个数字的传送，没有考虑锁链绑定的情况。

### 解决方案
修改 `processTeleportPortal` 函数：
1. 检测待传送的数字是否是锁链方块或锁链绑定的目标方块
2. 如果是锁链绑定的一部分，先计算两个方块的相对位置（dr, dc）
3. 寻找一个合适的空位对：先尝试以目标位置为基准，再尝试以锁链位置为基准
4. 找到合适位置后，将两个数字一起传送到新位置，保持相对位置不变
5. 更新 `chainPair.chainPos` 和 `chainPair.targetPos` 到新位置
6. 如果找不到合适的位置对，回退到只传送单个数字的原逻辑

## 问题 4：多个锁链模块问题

### 问题现象
棋盘上会出现多个锁链模块，导致两个锁链模块相连时直接解除了锁链。

### 问题原因
1. 在 `addRandomTile` 函数中，生成锁链时没有检查棋盘上是否已经存在锁链
2. 两个锁链模块相遇时可能发生合并，导致混乱
3. 锁链解除后没有冷却时间，可以立即生成新的锁链

### 解决方案
1. **添加 `chainCooldown` 字段**：记录锁链冷却时间

2. **修改锁链生成条件**：
   - 在 `addRandomTile` 中添加检查：`!this.hasChainCell() && this.chainCooldown === 0`
   - 确保同一时间棋盘上只能有一个锁链
   - 冷却期间不能生成新的锁链

3. **添加 `releaseChain` 辅助函数**：
   - 将锁链单元格转为普通数字
   - 设置 `chainPair = null`
   - 启动 5 步冷却时间（使用 `COOLDOWN_MOVES` 常量）

4. **替换所有锁链解除逻辑**：
   - `updateChainTimer`：倒计时结束时调用 `releaseChain()`
   - `updateChainPairAfterMerge`：找不到锁链或目标时调用 `releaseChain()`
   - `maintainChainAdjacency`：找不到锁链时调用 `releaseChain()`

5. **冷却时间递减**：
   - 在 `decrementCooldowns` 中添加 `chainCooldown` 递减逻辑

6. **防止两个锁链合并**：
   - 在 `canMergeWithChainRules` 中添加检查：两个都是锁链时不能合并

7. **状态持久化**：
   - 在 `serializeState`、`restoreState`、`GameSnapshot`、`undo()` 中支持 `chainCooldown` 的保存和恢复

## 问题 6：锁链分段/阻挡物策略

### 问题现象
1. 其他数字穿过锁链数字合并（锁链未起到阻挡作用）
2. 传送阵数字被错误传送（非锁链问题，一并修复）
3. 未绑定锁链不能移动（矫枉过正）
4. 绑定后锁链无法参与合并（过度阻挡）
5. 锁链无法与冰冻数字绑定

### 问题原因
锁链方块是否应作为分段阻挡物，经历了三次迭代：
1. **初始**：chain 不作为阻挡物 → 其他数字可以穿过锁链合并
2. **第一次修复**：将 chain 作为阻挡物（`cell.isChain()`） → 未绑定的 chain 也不能移动了
3. **第二次修复**：只有已绑定的 chain 作为阻挡物（`cell.isChain() && this.chainPair !== null`） → 已绑定的 chain 被单独分段，无法参与合并
4. **最终方案**：chain 不作为分段阻挡物，由 `canMergeWithChainRules` 控制合并规则

此外，`tryBindChain` 的条件 `!neighbor.isFrozenNumber()` 明确排除了冰冻数字。

### 解决方案
1. **最终分段策略**：chain 不作为分段阻挡物，从分段逻辑中移除所有 chain 相关条件
   - 分段逻辑只保留 `cell.isWoodBlock() || cell.isFrozenNumber()`
   - 静态段判断只检查木头、冰冻、传送门
   - 冰冻数字合并循环移除对 chain 的 break 检查

2. **合并规则由 `canMergeWithChainRules` 统一控制**：
   - 两个都是 chain：不能合并
   - 未绑定（`chainPair === null`）且有一方是 chain：不能合并
   - 已绑定的 chain 和 target 之间：不能合并
   - 已绑定的 chain 与其他相同数字：可以合并

3. **允许与冰冻数字绑定**：
   - 移除 `!neighbor.isFrozenNumber()` 限制，改为 `(neighbor.isNumber() || neighbor.isFrozenNumber()) && !neighbor.isChain()`

4. **传送阵修复**（一并修复）：
   - 重写 `processTeleportPortal`，只有当数字从传送阵一侧移动到另一侧时才传送

## 问题 7：动画残影与闪烁

### 问题现象
1. 数字移动时有明显的残影，影响游戏体验
2. 修复残影后，趣味模式下的模块在滑动时会不断闪烁

### 问题原因
1. **残影原因**：动画流程中，`render()` 立即将最终状态的真实方块渲染到最终位置，同时 ghost 方块从原始位置滑向最终位置，两者同时可见造成残影

2. **闪烁原因**：残影修复中将所有方块（包括木块、传送门等静态元素）设置为 `visibility: hidden`，但这些静态元素没有对应的 ghost 方块在滑动，隐藏它们会造成"消失→出现"的闪烁

### 解决方案
1. **只隐藏有对应 ghost 动画的方块**：动画开始后，只将 merge 位置对应的真实方块设为 `visibility: hidden`，不隐藏静态元素
2. **ghost 方块正常执行滑动动画**：此时只有 ghost 可见，无残影
3. **动画结束后恢复**：移除 ghost 方块，将隐藏的真实方块恢复为 `visibility: visible`
4. **合并弹跳动画**：对合并方块执行 pop 缩放动画

## 问题 8：锁链倒计时显示与绑定后合并问题

### 问题现象
1. 锁链倒计时为 0 时仍然显示 0，给玩家带来困扰（事实上此时锁链已经解开，但显示 0 让玩家误以为还没解锁）
2. 滑动合并逻辑问题：锁链数字在下方，其他数字在上方，向上滑动时上面的数字竟然向下滑动与锁链数字合并，不符合游戏逻辑

### 问题原因
1. **倒计时显示问题**：`updateChainTimer` 先将 `remainingMoves` 减 1，再判断是否 `<= 0` 才释放锁链。当倒计时从 1 变为 0 时，UI 会先显示 0，然后才释放锁链
2. **滑动合并问题**：`processRowLeft` 的分段逻辑中只将 `woodBlock` 和 `frozenNumber` 作为障碍物，chain 单元格没有被当作障碍物，导致其他数字可以穿过 chain 单元格进行合并，甚至出现反向移动

### 解决方案
1. **倒计时显示最小值**：在 UI 渲染中，chain 单元格的倒计时显示使用 `Math.max(1, data.chainPair.remainingMoves)`，确保显示的最小倒计时为 1
2. **分段逻辑恢复原始状态**：chain 不作为分段阻挡物，合并控制完全由 `canMergeWithChainRules` 统一管理

## 问题 9：锁链绑定前后行为区分

### 问题现象
1. 锁链数字绑定前无法移动（之前修复中矫枉过正）
2. 锁链数字绑定后无法参与合并（过度阻挡）

### 问题原因
之前修复将所有 chain 单元格都作为障碍物处理，没有区分绑定前后的状态：
- **绑定前**（`chainPair === null`）：chain 应该可以自由移动，但不能合并
- **绑定后**（`chainPair !== null`）：chain 可以与其他数字合并（但链和目标之间不能合并），合并会减少倒计时

### 解决方案
1. **分段逻辑中移除所有 chain 条件**：chain 不作为分段阻挡物，无论绑定前后
2. **合并规则由 `canMergeWithChainRules` 统一控制**：
   - 未绑定 chain：不能合并（只能移动和连接）
   - 已绑定 chain：可以与其他相同数字合并，但链和目标之间不能合并
3. **frozen number 搜索的 break 条件**：只有当绑定 chain 值不同时才 break（因为不同值的绑定 chain 会阻挡路径），同值时允许继续到合并判断

## 问题 10：撤销键限制与传送阵消失问题

### 问题现象
1. 趣味模式撤销键有次数限制（显示数字"5"），但需求改为不限次数
2. 传送阵无法消失：数字经过传送阵后，传送阵仍然存在于棋盘上

### 问题原因
1. **撤销限制**：`canUndo` getter 中检查 `undoRemaining > 0`，`undo()` 方法中扣减 `undoRemaining`
2. **传送阵不消失**：`processTeleportPortal` 中，当传送阵位置被滑入的数字占据时（`portalCell.hasValue()` 为 true），函数直接 `return` 而没有清除 `teleportPortalPosition`

### 解决方案
1. **取消撤销限制**：
   - `canUndo` getter 中移除 `undoRemaining` 检查，只保留 `this.history.length > 0`
   - `undo()` 方法中移除 `undoRemaining` 检查和扣减逻辑
   - UI 中隐藏撤销键的数字显示（`undoCountEl.style.display = 'none'`）

2. **修复传送阵消失**：
   - 当传送阵位置被数字占据时，设置 `teleportPortalCooldown` 并将 `teleportPortalPosition` 置为 null，然后 return

## 问题 11：锁链连接停滞与倒计时提前解锁

### 问题现象
1. 锁链数字上下都有数字时，向上滑动后出现明显"停滞"才出现连接
2. 锁链倒计时还有 3，滑动一次但没有产生任何合并，锁链却直接解锁

### 问题原因
1. **连接停滞**：当锁链第一次绑定时（`!wasBoundBefore`），`maintainChainAdjacency` 仍然被执行。该函数发现链和目标不相邻，会强制把链移动到目标旁边的空位，造成视觉上的跳跃/停滞

2. **倒计时提前解锁**（多个 bug 叠加）：
   - **`updateChainTimer` 使用了已被更新的位置**：`updateChainPairAfterMerge` 和 `maintainChainAdjacency` 在 `updateChainTimer` 之前执行，更新了 `chainPair.chainPos` 和 `chainPair.targetPos`，导致 `updateChainTimer` 拿到的不是原始位置
   - **`findOriginalTargetPos` 查找逻辑有缺陷**：只按值搜索第一个匹配的非 chain 单元格，如果棋盘上有多个相同值的数字，可能找到错误的位置
   - **`didCellMerge` 判断过于宽松**：当 `skipBlockerCheck = true` 时，只要同行/列有合并且结果值匹配就返回 true，没有验证原始位置的单元格是否真的参与了合并

### 解决方案
1. **修复连接停滞**：只在已经绑定时（`wasBoundBefore`）才执行 `maintainChainAdjacency`，刚绑定时跳过

2. **修复倒计时提前解锁**：
   - 在 `move` 函数中保存原始 chainPair 位置 `originalChainPair`
   - `updateChainTimer` 使用 `originalChainPair` 的精确位置，不再搜索
   - `didCellMerge` 增加 `cellChanged` 前置检查：只有原始位置的单元格确实发生了变化时，才继续判断是否参与了合并

## 问题 13：锁链不对齐时滑动导致锁链分离

### 问题现象
锁链上下相邻（同一列不同行）时，向左滑动，上面的数字被卡住不动，但下面的数字可以自由向左滑动，导致锁链分离解除，不符合锁链模块表现说明中场景3的规定。

### 问题原因
1. **`prepareChainForMovement` 不对齐时直接返回**：当锁链上下相邻左右滑动时，`chainAndTargetAligned = false`，函数直接 `return`，没有设置任何标记
2. **`constrainChainMovement` 无约束**：因为 `_chainMovementPrepared = false`，函数直接返回，没有做任何阻止移动的约束
3. **移动逻辑逐行独立处理**：第0行和第1行的处理互不影响，第1行的数字没有被约束

### 解决方案
1. **修改 `prepareChainForMovement`**：不对齐时设置 `_chainBlocked = true` 和 `_chainMovementPrepared = true`，记录原始位置
2. **修改 `constrainChainMovement`**：`_chainBlocked` 时直接返回，跳过整体移动逻辑
3. **新增 `restoreChainBlockedMovement` 函数**：在移动完成后做后处理，检测锁链方块是否参与了合并：
   - 如果任一方合并了（`mergePositions` 中有原值2倍的结果在附近）：允许移动（不恢复）
   - 如果都没合并但位置变了：恢复到原位（阻止独立滑动）
4. **在 `move` 函数中调用**：在 `finalizeChainMovement` 之前调用 `restoreChainBlockedMovement`

## 问题 14：锁链方块无法参与合并

### 问题现象
锁链连接后，即使旁边有相同值的数字，锁链方块也无法与其合并。例如：`[4, 4(chain), 4(target), _]` 向左滑动时，左边的4和4(chain)应该合并成8(chain)，但实际上4(chain)完全不能移动也不能合并。

### 问题原因
1. **`canMergeWithChainRules` 阻止了 `_chainBlocked` 时的所有合并**：上一轮修复中添加了 `if (this._chainBlocked)` 判断，完全阻止了锁链对参与合并
2. **`constrainChainMovement` 强制覆盖行首数字**：原实现将锁链对强制放到行首固定位置 `[0]` 和 `[1]`，覆盖了原本在那里的数字，导致合并无法发生

### 解决方案
1. **移除 `canMergeWithChainRules` 中的 `_chainBlocked` 合并阻止**：不对齐时锁链对应该可以参与合并，只是不能独立滑动
2. **简化 `constrainChainMovement`**：不再强制移动锁链对的位置，只做阻挡检查（前方有木块或不同值数字时标记 `_chainBlocked`）

## 问题 15：锁链对互相合并（倒计时未结束）

### 问题现象
两个4通过锁链左右相连，倒计时为2，向右滑动时锁链消失，两个4合并为8。但倒计时没有结束，锁链连接的数字不应该能互相合并。

### 问题原因
`processRowRight` 反转行后调用 `processRowLeft`，但 `chainPair.chainPos` 和 `chainPair.targetPos` 没有同步反转。段处理逻辑中传入 `canMergeWithChainRules` 的坐标是反转后的列索引，但 `canMergeWithChainRules` 用原始位置来判断是否是锁链对，导致位置检查失效：
- 原始行 `[_, 4(chain), 4(target), _]`：chainPos=(row,1)，targetPos=(row,2)
- 反转后行 `[_, 4(target), 4(chain), _]`：4(target)在列1，4(chain)在列2
- `canMergeWithChainRules` 检查 `(row,1)==chainPos` 为 true，但实际单元格是4(target)不是chain
- 位置检查混乱，锁链对的"不能互相合并"规则失效

### 解决方案
在 `processRowRight` 中，调用 `processRowLeft` 前后临时反转 `chainPair` 位置：
- 水平滑动时反转列索引：`col → BOARD_SIZE - 1 - col`
- 垂直滑动时反先行索引：`row → BOARD_SIZE - 1 - row`
- 调用完毕后恢复原始位置

---

## 问题 16：不对齐滑动时锁链对成员错误参与合并

### 问题现象
第三行 `[4, 2, 2(chain), 空]` 向左滑动，锁链对上下相邻（第三行第三列2和第四行第三列4）。向左滑动时，第三行第二列的普通数字2与第三列的锁链数字2错误合并，导致第三行第二列的数字消失。

### 问题原因
`canMergeWithChainRules` 函数缺少 `_chainBlocked` 状态检查。当 `prepareChainForMovement` 检测到锁链对不对齐滑动并设置 `_chainBlocked = true` 后，合并逻辑仍然允许普通数字与锁链数字合并。

根据《锁链模块表现说明》场景3：
> 锁链和目标上下相邻（同一列不同行），玩家左右滑动。
> - **两个都不动**！（滑动方向不在它们的连线上）

### 解决方案
修改 `canMergeWithChainRules` 函数，增加 `_chainBlocked` 检查：
- 当 `_chainBlocked = true` 时，锁链对的任何成员都不参与合并
- 只限制合并，不影响其他普通数字之间的合并

---

## 问题 17：_chainBlocked 过度阻止合并

### 问题现象
第一行 `[32, 8, 4(chain), 2(chain)]`，第二行 `[2, 空, 空, 2]` 向上滑动时，第二行第四列的2无法与第一行第四列的2(chain)合并。

### 问题原因
问题16的修复过度：`_chainBlocked` 阻止了**所有**与锁链对相关的合并，包括其他数字滑过来与锁链数字合并。

### 关键理解
- `_chainBlocked = true` 只表示**锁链对不能独立移动**（通过 `restoreChainBlockedMovement` 恢复位置）
- `_chainBlocked` **不应该限制合并** —— 其他数字可以正常滑过来与锁链数字合并（原地合并）

### 解决方案
移除 `canMergeWithChainRules` 中的 `_chainBlocked` 检查，`_chainBlocked` 只在 `restoreChainBlockedMovement` 中用于判断是否需要恢复位置。

## 问题 18：restoreChainBlockedMovement 逻辑错误

### 问题现象
第二行 `[8, 空, 2, 2(chain)]` 向左滑动时，数字2停留在第三列，无法滑动到第二列。

### 问题原因（两个bug）：

1. **合并检测错误**：
```javascript
if (dist <= 1) { chainMerged = true; }  // ❌ 距离判断太严格
```
向左滑动时，合并发生在左侧位置，距离原始位置可能大于1，导致 `anyMerged = false`，错误地进入恢复逻辑。

2. **恢复搜索错误**：
```javascript
for (let i = 0; i < BOARD_SIZE; i++) {
  for (let j = 0; j < BOARD_SIZE; j++) {
    if (c.value === origCell.value && c.type === origCell.type) {
      // ❌ 可能找到另一个锁链对成员！
    }
  }
}
```
搜索范围是整个棋盘，可能找到错误的单元格（另一个锁链对成员），然后错误地移动它。

### 解决方案
1. **合并检测**：改用已有的 `didCellMerge` 函数，准确检测合并
2. **恢复搜索**：
   - 只在**同一行/列**搜索（根据锁链对是水平还是垂直）
   - 明确**排除另一个锁链对成员**的位置，避免找错

## 问题 19：processRowRight 位置反转逻辑不完整

### 问题现象
锁链对 `(0,3)=4(chain)` 和 `(1,3)=2(chain)` 上下相邻，向右滑动时，第二行第三列的2无法与第四列的2(chain)合并。

### 问题原因
`processRowRight` 中的位置反转逻辑条件太严格：
```javascript
if (isHorizontal &&
    rowIdx === this.chainPair.chainPos[0] &&
    rowIdx === this.chainPair.targetPos[0]) {  // ❌ 需要两个都满足
  // 反转位置
}
```
当锁链对上下相邻（垂直），处理第二行（`rowIdx=1`）时：
- `rowIdx === chainPos[0]` → `1 === 0` → false
- `rowIdx === targetPos[0]` → `1 === 1` → true
- 条件用 `&&` 连接 → **整体 false → 不反转位置！**

结果：`canMergeWithChainRules` 收到错误的位置，合并判断失效。

### 解决方案
分别检查 `chainPos` 和 `targetPos`，只要当前处理的行/列包含任一成员，就反转对应位置：
```javascript
if (isHorizontal) {
  if (rowIdx === this.chainPair.chainPos[0]) {
    this.chainPair.chainPos = [this.chainPair.chainPos[0], BOARD_SIZE - 1 - this.chainPair.chainPos[1]];
  }
  if (rowIdx === this.chainPair.targetPos[0]) {
    this.chainPair.targetPos = [this.chainPair.targetPos[0], BOARD_SIZE - 1 - this.chainPair.targetPos[1]];
  }
}
```

## 问题 20：mergeToChain 合并位置错误

### 问题现象
第三行锁链对 `[2(chain), 2(target)]` 左右相邻，向上滑动（不对齐滑动）。列1 `[8, 2, 2(target是chain), 2]` 向上滑动时，target 从 `(2,1)` 移动到 `(1,1)` 与 2 合并，锁链对位置错位 → 解除。

### 问题原因
`processRowLeft` 中合并到锁链时的位置逻辑错误：
```javascript
} else if (mergeToChain) {
  newCell = Cell.chain(mergedValue);
  mergePosInSegment = processed.length;  // ❌ 总是合并到左边！
}
```

对比冰冻数字的正确处理：
```javascript
if (mergeAtIceBlock) {
  mergePosInSegment = currentIsFrozen ? current[0] : next[0];  // ✅ 合并到冰冻位置
}
```

冰冻数字合并到自己的位置（不动），但锁链合并到左边位置（移动了），导致锁链成员错位，锁链对不再相邻而解除。

### 解决方案
合并到锁链时，使用锁链所在的位置：
```javascript
} else if (mergeToChain) {
  newCell = Cell.chain(mergedValue);
  mergePosInSegment = currentIsChain ? current[0] : next[0];  // ✅ 合并到锁链位置
}
```

## 问题 21：合并顺序错误（不对齐滑动时）

### 问题现象
列1 `[8, 2, 2(chain), 2]` 向上滑动（不对齐滑动）时：
- 标准逻辑：行1的2与行2的2(chain)合并 → 锁链移动
- 用户期望：行3的2与行2的2(chain)合并 → 锁链不动

### 问题原因
`valuesWithIndices` 按从上到下顺序排列，合并也是从上到下依次进行。普通数字在锁链前面时会先合并，导致锁链移动。

### 解决方案
当 `_chainBlocked = true`（不对齐滑动）时，如果 `current` 是普通数字，`next` 是锁链且值相同，**跳过合并**，让后面的数字先与锁链合并：
```javascript
if (this._chainBlocked && !currentIsChain && nextIsChain) {
  processed.push(current);
  i++;
  continue;  // 跳过，让后面的数字与锁链合并
}
```

**关键条件**：只在 `_chainBlocked = true` 时生效，不影响正常的对齐滑动场景。
