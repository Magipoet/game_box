# 记忆配对游戏 - 迭代方案2

## 一、游戏玩法扩展（核心玩法迭代）

### 1. 新增游戏模式
现有代码已经支持 `GAME_MODES.NORMAL`（常规）和 `GAME_MODES.TIMED`（限时）两种模式，可以进一步扩展：

| 模式名称 | 核心玩法 | 关联现有代码 |
|---------|---------|------------|
| **移动步数模式** | 限制总翻牌步数，考验记忆精准度 | 已有 `moves` 计数器 [game.js](file:///remote-home/share/lijl/game_box/games/memory-match/js/game.js) |
| **挑战模式** | 预设特殊关卡（全炸弹、限时+限步叠加） | 可复用 `gameLevels` 配置结构 |
| **盲盒模式** | 每次翻开卡片有概率出现道具（洗牌、提示、免翻一次） | 可在 `flipCard()` [game.js#L563](file:///remote-home/share/lijl/game_box/games/memory-match/js/game.js#L563) 中增加随机事件触发 |
| **每日谜题** | 每日固定一张特殊地图，全服玩家同步挑战 | 复用 `renderLevelSelectMap` + 增加日期判断逻辑 |
| **多人对战模式** | 两人轮流翻牌，配对成功继续翻，配对失败换人 | 复用翻牌逻辑，增加 turn 状态变量 |

### 2. 新增卡片机制
现有 `💣 炸弹` 是一种特殊卡片，可以继续增加：

| 卡片类型 | 效果 | 代码切入点 |
|---------|------|----------|
| **🧊 冰冻卡** | 配对失败时，一张卡片不翻回（保留记忆提示） | `unflipCards()` [game.js#L809](file:///remote-home/share/lijl/game_box/games/memory-match/js/game.js#L809) 中加例外判断 |
| **🔀 洗牌卡** | 翻开后，剩余未匹配卡片随机重排 | 可在 `cards[]` 数组中新增 isShuffle 标记 |
| **💎 万能卡** | 可以与任意卡片配对一次 | 修改 `checkMatch()` [game.js#L600](file:///remote-home/share/lijl/game_box/games/memory-match/js/game.js#L600) 的匹配逻辑 |
| **⏱️ 加时卡** | 限时模式下额外增加时间 | 在 `startCountdown()` 中增加 bonusTime 变量 |
| **⭐ 双倍星卡** | 这张卡片配对成功，整关星数+1 | 星星结算逻辑处扩展 |

### 3. 道具系统
玩家可以在关卡前/关卡中购买和使用道具：
- 💡 **提示道具**：自动高亮一对相同的卡片 3 秒
- 🔄 **洗牌道具**：重置所有未匹配卡片的位置
- 🛡️ **护盾道具**：免疫下一次炸弹爆炸
- 🎯 **透视道具**：开局时所有卡片短暂显示 2 秒
- ⏸️ **冻结道具**：限时模式下暂停倒计时 10 秒

道具系统可复用现有体力 `STAMINA_CONFIG` 的配置结构，新增道具库存变量、购买弹窗。

## 四、社交与竞技（互动层面）

### 1. 排行榜系统
- **好友排行**：接入微信/QQ等社交登录后的好友排行
- **全服排行**：每日/每周/每月限时模式最快通关榜
- **模式分区**：常规模式三星总数榜、限时模式累计通关榜
- **本地排行**：无登录情况下的本地成绩记录（localStorage 已有 `saveGameData` 基础）

### 2. 社交功能
| 功能 | 实现思路 |
|------|---------|
| **关卡分享** | 通关后生成精美卡片（关卡、星数、用时），支持分享到社交平台 |
| **好友对战** | 创建房间 → 生成邀请码 → 两人同步对战同一关卡，先完成者胜 |
| **好友赠礼** | 好友之间赠送体力（每天3次赠送机会） |
| **排行榜助力** | 点赞好友成绩，获得点赞奖励 |

### 3. 竞技与赛事
- **周末杯赛**：限时开放特殊关卡，玩家比拼通关速度
- **赛季系统**：2个月为一赛季，赛季结束排名重置并发放皮肤奖励
- **天梯模式**：匹配相近水平的玩家进行关卡竞速，积分段位制（青铜→白银→黄金→钻石→大师）

## 五、技术与性能优化

### 1. 代码架构优化
| 方向 | 具体内容 |
|------|---------|
| **模块化** | 目前 game.js 文件 800+ 行，可拆分：`card.js`（卡片逻辑）、`level.js`（关卡管理）、`stats.js`（统计）、`animation.js`（特效） |
| **TypeScript 化** | 增加类型约束，减少运行时 bug |
| **状态管理** | 目前 state.js 中大量全局变量，可引入 Pinia/Vuex/Redux 等状态管理方案 |
| **游戏循环重构** | 用 requestAnimationFrame 实现统一的游戏循环入口，便于后续扩展 |

### 2. 性能优化
| 方向 | 具体内容 |
|------|---------|
| **移动端适配** | 现有响应式布局基础，进一步优化小屏机型（iPhone SE 等 320px 宽机型）的棋盘缩放 |
| **图片资源** | 目前使用 emoji，加载快；如果替换为图片资源，可引入 WebP、懒加载、雪碧图 |
| **动画性能** | 频繁的重绘/重排区域使用 `will-change: transform`、CSS3 硬件加速 |
| **内存泄漏** | 清理 `setTimeout` / `setInterval`（现有 `clearTutorialAutoAdvanceTimer` 思路可扩展到全局） |
| **首屏加载** | Critical CSS 内联、JS 按路由懒加载、Service Worker 离线缓存 |

### 3. 数据埋点与 A/B 测试
| 方向 | 具体内容 |
|------|---------|
| **关键节点埋点** | 记录每关通关时长、翻牌次数、失败原因（炸弹/超时/体力），用于后续关卡难度调整 |
| **漏斗分析** | 启动游戏 → 完成教程 → 通过第1关 → 付费 的转化路径分析 |
| **A/B 测试** | 测试不同：<br>• 教程步骤数量<br>• 体力恢复间隔<br>• 炸弹出现关卡<br>• 配色方案<br>找到留存/付费最优解 |

### 4. 跨平台与兼容性
| 方向 | 具体内容 |
|------|---------|
| **PWA 化** | 添加 `manifest.json` 和 Service Worker，支持"添加到主屏幕"并离线游玩 |
| **小程序/快应用适配** | 用 Taro / Uni-App 等框架编译为微信小程序、抖音小程序 |
| **桌面客户端** | 用 Electron / Tauri 打包为 Windows / macOS 客户端 |
| **暗模式支持** | 适配浏览器 `prefers-color-scheme: dark` |
| **无障碍 (a11y)** | ARIA 属性、键盘导航、屏幕阅读器友好 |

## 六、内容扩展（长线运营）

### 1. 关卡设计
现有 `gameLevels` 配置结构可无限扩充：
- **难度曲线优化**：基于用户数据，优化 4×3 / 4×4 / 5×4 / 6×5 / 6×6 等规格的出现时机
- **主题关卡包**：每包 10-20 关，围绕特定主题（动物、美食、太空、节日等）+ 专属背景
- **隐藏关卡**：集齐 3 星解锁高难度隐藏关卡
- **关卡编辑器**：UGC 编辑器，玩家自己设计关卡并分享

### 2. 剧情与世界观
- **主线剧情**：失忆的小动物找朋友（每一关配对成功就是"找回一个朋友"）
- **角色系统**：可解锁多个角色，每个角色有被动技能（+5秒限时、免疫一次炸弹等）
- **章节式推进**：每 20 关一个章节，通关解锁剧情动画

### 3. 活动运营
- **节日活动**：春节/圣诞/情人节 推出限定关卡、限定主题、节日任务
- **联动活动**：与 IP 联动（如表情包 IP、动漫 IP），替换卡片内容为联动元素
- **新手福利**：前 7 天每日登录奖励，增加次日留存

## 建议优先级（ROI 排序）

如果要选择**短期（1-2周）可落地**、**用户价值高**的迭代方向，建议按以下顺序：

1. ✅ **P0：体验类问题修复**（目前正在进行的教程、交互 bug 修复）
2. 🔧 **P1：通关动画 + 音效分层 + 移动端适配**（提升核心玩法爽感）
3. 🎯 **P2：道具系统（提示 + 洗牌）+ 成就系统**（增强目标感）
4. 💰 **P3：每日签到 + 每日任务**（提升次日/7日留存）
5. 🧩 **P4：盲盒模式 + 万能卡/冰冻卡**（玩法深度）
6. 📱 **P5：PWA 化 + 暗模式**（技术体验）
7. 🏆 **P6：本地排行榜 + 关卡分享卡片**（社交起步）
8. 🎨 **P7：主题扩充 + 关卡地图美化**（视觉丰富度）

后续中长期再考虑多人对战、跨平台适配、赛季系统等重功能。
